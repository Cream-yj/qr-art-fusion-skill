# 实际文件验码与结果表达

## 分开记录四件事

1. **生成流程：**实际执行了哪个生成、控制或编辑后端，是否只完成配置。
2. **视觉完成度：**用户要求的构图、角色、材质和修整是否满足。
3. **电脑解码：**哪些解码器在什么文件和条件下读到了原内容。
4. **使用场景实测：**具体手机、目标应用、印刷、观看距离与光照是否测试。

模型已经加载、生成图看起来像码、目标矩阵文件未变，都不能替代实际文件解码。读出同一链接也不证明该链接当前可访问；除非任务需要，不必访问扫码内容。

## 测试哪些文件

- 原始普通二维码的识别基线。
- 真正保存并交付的无损文件与 JPG，记录文件散列和尺寸。
- 用户主要使用的分享文件；由同一母版导出也不能省略检测。
- 根据需要测试保持比例的缩图、JPEG 压缩或旋转模拟，注明尺寸、算法、质量等条件。

不要把纵向海报强行缩成正方形来测试。不要用孤立的局部码区、简洁测试码、旧 PNG 或一次重新渲染的图代替实际交付文件。

## 解码器与预处理

可使用 ZXing-C++、Apple Vision、Apple CoreImage、OpenCV WeChat QRCode 等可用路径；本次选择以用户验收和运行环境为准。Apple 工具依赖相应平台，缺少时记“未测试”。OpenCV WeChat 在电脑中的返回结果不等于微信手机应用实测。

对原文件和显式预处理结果分别记录。灰度、对比度、模糊或替换阈值策略后才成功的结果，不能计作未预处理原文件通过。一个库的多种配置也不等于多套完全独立解码器。

至少区分：

| 状态 | 含义 |
|---|---|
| 通过 | 解码器运行完成，返回内容与预期一致 |
| 未通过 | 运行完成但没有读出预期内容，包括错码 |
| 未测试 | 当前环境或本次范围没有执行 |
| 运行错误 | 工具调用或运行失败，不能伪装成解码失败 |

## 每份记录包含什么

- 实际文件名、散列、尺寸、格式，以及生成/合成版本。
- 预期内容或本地私有内容引用；公开报告使用已授权的公开内容或匿名化标识。
- 各解码器名称、可取得的版本与设置、状态及返回值比对。
- 预处理、缩放和压缩条件；原文件结果单独分列。
- 实际手机/应用/印刷的测试状态；没有执行就写未测试。

不为达到漂亮的通过计数而只报告有利的解码器、尺寸或预处理。某文件“3/4 通过”要保留具体通过与失败项；不能沿用其他文件的结果。

## 失败后的决策

先检查码区尺寸与位置、定位、静区、功能区、关键暗部、高光面积、压缩和缩放条件。中心采样与阈值诊断可帮助选择修复范围；它们不是解码错误率，也不构成扫码成功证明。

若修复影响已经确认的视觉风格，展示具体改动与真实测试结果。达到本次约定的检查后停止无依据的重复试验；未满足要求的版本可以交付供讨论，但明确其状态。

### 报告示例

```text
已修整指定区域，其他图层保持原版。
实际 PNG 与 JPG：列出每个解码器的结果与读取内容是否一致。
主要分享尺寸：单独列出结果及缩放方式。
真实手机 / 目标应用 / 印刷：未测试，或填写真实设备与条件。
```

这是写法示例，没有预填任何成功成绩。二维码艺术化的效果与最终验收要由当前任务的证据决定。
